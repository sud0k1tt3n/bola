# Дообучение модели на своей разметке

Цепочка: экспорт из CVAT → `prepare_dataset.py` → обучение (на своём компьютере или в
Colab) → `models/best.pt` → перезапуск сервера. Интерфейс и геопривязку менять не нужно:
модель выдаёт те же 3 класса, что ждёт backend.

## 1. Экспорт из CVAT

Задача → Actions → Export task dataset → формат **YOLO 1.1**, «Save images» включено.
Получится zip с `obj.names`, `obj_Train_data/…` — его и подаём дальше как есть.

## 2. Подготовка датасета

```bash
cd backend
python prepare_dataset.py путь/к/task_…_yolo.zip
```

Скрипт кладёт результат в `data/hazards/` и печатает отчёт (он же — `data/hazards/REPORT.md`):

| В разметке | → Класс модели | Почему |
|---|---|---|
| flooded_road, flooded_area | `flooding` (красный) | подтопление |
| collapsed_bridge, damaged_bridge | `bridge_collapse` (красный) | повреждённый мост считаем непроходимым, пока не доказано обратное |
| fallen_tree_on_road | `fallen_tree` (жёлтый) | |
| fallen_tree_off_road | выброшен | не мешает проезду; с `--keep-off-road-trees` станет `fallen_tree` |
| normal_bridge | выброшен | целый мост — фон; кадры остаются как «трудные негативы» |
| snow_drift, ice_jam | выброшен | вне 3 классов ТЗ |

Правила — словарь `CLASS_MAP` в начале `prepare_dataset.py`. Появится новый класс
разметки — скрипт остановится и попросит дописать для него правило.

**Кадры без единой рамки по умолчанию не берутся.** В CVAT пустой файл разметки значит и
«опасностей нет», и «ещё не дошли руки». Если в таком кадре поваленное дерево, модель
выучит «дерево — это фон» и станет хуже. Когда пустые кадры проверены и там действительно
чисто — запускайте с `--keep-empty`, это полезные негативы.

## 3. Обучение

### На своём компьютере (CPU подходит)

```bash
cd backend
pip install -r requirements.txt
python train.py train          # по умолчанию берёт data/hazards/hazards.yaml
python train.py eval           # таблица P / R / mAP по классам → docs/TEST_PROTOCOL.md
```

На ~130 кадрах YOLO11n на обычном ноутбуке учится порядка 20–60 минут; с GPU — несколько
минут. Остановится сам, если 40 эпох подряд качество на валидации не растёт. Мало памяти —
`--batch 8`. Mac на M1 и новее — `--device mps`.

В конце лучшие веса копируются в `backend/models/best.pt` (прежние сохраняются как
`best.prev.pt`), графики — в `backend/runs/hazards/` (`results.png`, `confusion_matrix.png`,
`val_batch0_pred.jpg` — предсказания на валидации, полезно глазами посмотреть).

### В Google Colab (бесплатный GPU)

1. Заархивируйте папку `data/hazards` в `hazards_dataset.zip` (или возьмите готовый архив).
2. Откройте `backend/train_colab.ipynb` в Colab, включите T4 GPU, запускайте ячейки по порядку.
3. Скачанный `best.pt` положите в `backend/models/best.pt`.

### Аугментации

По умолчанию — щадящие (поворот ±10°, без переворота вверх ногами), потому что в текущей
разметке много наземных фото. Когда датасет станет чисто аэрофотосъёмкой, учите с
`--aerial`: поворот на любой угол и вертикальное отражение — у кадра сверху нет «верха».

## 4. Проверка в приложении

```bash
uvicorn main:app --port 8000
```

Жёлтая плашка «Демо-режим» в шапке должна пропасть, в «Что нашла модель» — `модель best.pt`.
Не запускайте с `RHD_DEMO=1` / `run_demo.py` — демо-режим игнорирует модель.
Если модель находит мало — сначала снизьте пороги `CLS_CONF` в `backend/config.py`
(например, до 0.20), посмотрите, что она видит, и только потом решайте, нужна ли разметка.

Вердикты оператора («Всё верно» / «Ложное срабатывание») копятся в базе — это готовый
материал для следующей итерации разметки.

## 5. Что сейчас с вашей разметкой (экспорт от 28.09.2026)

450 кадров, размечено 133; рамок 196, после перевода в 3 класса осталось 149:

| Часть | Кадров | flooding | bridge_collapse | fallen_tree |
|---|---|---|---|---|
| train | 106 | 66 | 7 | 47 |
| val | 27 | 14 | 2 | 13 |

Что стоит поправить до следующего обучения — по убыванию пользы:

1. **317 кадров без разметки, и многие из них не пустые.** Среди них есть кадры с явно
   поваленными деревьями и мостами — похоже, их просто не успели разметить. Список —
   `data/hazards/unlabeled.txt`. Особенно ценны 97 кадров `bridge_*`: это аэросъёмка, как у
   БАС, а размечено из этой серии всего 18.
2. **`bridge_collapse` — 9 рамок.** С таким количеством класс не выучится; метрика по нему на
   двух примерах в валидации ничего не скажет. Нужно хотя бы 100–150 примеров повреждённых
   и обрушенных мостов, иначе честнее временно не обещать этот класс.
3. **Больше половины кадров — наземные фото** (`ia_*`: улицы после урагана, вид с уровня
   человека), а приложение работает со снимками сверху. Модель научится, но на кадрах БАС
   будет заметно хуже, чем покажут метрики. Добавляйте аэрофото.
4. **Проверьте, как размечено подтопление.** Часть рамок `flooded_road` стоит на мокрых улицах
   с поваленными деревьями, иногда почти совпадая с рамкой дерева. Договоритесь в команде:
   `flooded_road` — это стоящая вода на полотне, а не мокрый асфальт.
5. Отдельной тестовой выборки нет — при 133 кадрах её не из чего выделить. Когда размеченных
   станет 400+, отложите 10–15% кадров **из других полётов** в `test` и не смотрите на них
   до финальной оценки.
